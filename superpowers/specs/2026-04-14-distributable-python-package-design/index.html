Distributable Python Package Notebook — Design Spec

Date: 2026-04-14
Course: PRG 400: Advanced Python
Output: prg400/DistributablePackage.ipynb

Goal

Teach PRG 400 students how to create, install, and distribute a Python package using setuptools + pyproject.toml. Students leave with a working, publishable package and a mental model of how the Python packaging ecosystem works.

Approach

Build-First: Students build a real package (texttools) from scratch, and each concept is introduced exactly when it's needed. Matches PRG 400 style — hands-on early, explain-as-you-go.

Sections

  1. Opening — What is a distributable package? Why not just share .py files?
  2. Anatomy — src/ layout, __init__.py, __version__, module structure
  3. pyproject.toml deep-dive — [project], [build-system], metadata, classifiers, dependencies
  4. Local install — pip install -e . (editable install), verifying with import
  5. Entry points — Creating a CLI command (texttools) from the package
  6. Testing — Writing and running pytest tests against the installed package
  7. Building — python -m build → .whl + .tar.gz artifacts explained
  8. Publishing — TestPyPI walkthrough (upload step is exercise, not run live)
  9. Versioning — SemVer, __version__, how to bump versions correctly
  10. Challenge — Students build their own mini package end-to-end

Example Package: texttools

A small string-utility package with: - texttools.core — functions: word_count(), reverse_words(), title_case_smart() - texttools.cli — entry point: texttools CLI command - __version__ = "0.1.0"

Simple enough to not distract from packaging concepts; real enough to demonstrate entry points and imports.

Style

Matches existing PRG 400 notebooks: - Rich markdown with tables and diagrams (ASCII) - Collapsible <details> for solutions - Runnable code cells with printed output - Challenge blocks at the end - No emojis beyond what's already consistent in the course

Constraints

  • setuptools + pyproject.toml only (no poetry/hatch)
  • Python 3.8+ compatible
  • All shell commands shown as %%bash cells or ! prefix for context
  • TestPyPI upload is shown as code but not executed live

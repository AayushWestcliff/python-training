FastAPI Teaching Notebook — Design Spec

Date: 2026-04-19
Course: PRG400 (Advanced Python)
Output file: prg400/FastAPI.ipynb

Goal

A standalone Jupyter notebook that teaches FastAPI from first principles up to JWT authentication, using a Travel System as the running domain. Students already know Pydantic, type hints, SQLAlchemy, and databases — those are prerequisites, not teaching targets.

Approach

Layered app with clear checkpoints (Option C): one travelapi/ codebase grows section by section. Each major section opens with a checkpoint code block students can paste to catch up. Sections are self-contained enough to understand in isolation but tell a coherent story when read in order.

Domain Entities

Entity Fields
Destination id, name, country, description, price_per_day
Trip id, destination_id, start_date, end_date, spots_available
Booking id, trip_id, user_id, status (pending / confirmed / cancelled)
User id, username, hashed_password, api_key

Section Plan

Section 0 — What We're Building

  • Overview of the Travel API and what students will have built by the end
  • Stack diagram: client → FastAPI → SQLite
  • Final endpoint table (all routes that will exist after Section 9)
  • Prerequisites and pip install command

Section 1 — First Routes

  • FastAPI() app instantiation
  • @app.get decorator, returning a plain dict
  • Running with uvicorn app.main:app --reload
  • Visiting /docs (Swagger UI) and /redoc
  • Mini challenge: Add a GET /health route returning {"status": "ok"}

Section 2 — Path & Query Parameters

  • Path parameters: GET /destinations/{destination_id}
  • Query parameters: GET /trips?country=France&max_price=200
  • Optional query params with Optional[str] = None
  • Type coercion (FastAPI converts string → int automatically)
  • Mini challenge: Add country filter to GET /destinations

Section 3 — Request & Response Models

  • Pydantic BaseModel for request body (DestinationCreate)
  • Separate response model (DestinationResponse) — why they differ
  • response_model parameter on route decorator
  • Field validation: Field(min_length=1), Field(gt=0)
  • 422 Unprocessable Entity walkthrough
  • Mini challenge: Add a description field with min_length=10 validation

Section 4 — SQLAlchemy Integration

  • SQLAlchemy models for all four entities
  • get_db dependency and Depends(get_db) pattern
  • Full CRUD for Destination: GET all, GET one, POST, DELETE
  • Checkpoint: complete main.py + database.py at start of section
  • Mini challenge: Add GET /destinations/{id} returning 404 if not found

Section 5 — Routers

  • Why routers: keeps main.py from growing unmanageable
  • APIRouter, prefix, tags
  • Split into: routers/destinations.py, routers/trips.py, routers/bookings.py
  • app.include_router() in main.py
  • Checkpoint: full project structure at start of section
  • Mini challenge: Create a routers/reviews.py with a single GET /reviews stub

Section 6 — Middleware

  • What middleware is and where it sits in the request lifecycle
  • BaseHTTPMiddleware — request logging (method, path, status, duration)
  • CORS middleware (CORSMiddleware) — why browsers need it
  • Adding a custom X-Process-Time response header
  • Mini challenge: Add an X-Request-ID header using uuid4()

Section 7 — API Key Authentication

  • APIKeyHeader from fastapi.security
  • Storing API keys on the User model
  • Security() dependency that validates the key against the database
  • Protecting POST /trips and POST /bookings routes
  • Returning 403 Forbidden for invalid keys
  • Mini challenge: Protect all DELETE routes with the same API key dependency

Section 8 — JWT Authentication

  • Why JWT over API keys (stateless, expiry, scopes)
  • python-jose for token encoding/decoding
  • passlib[bcrypt] for password hashing
  • POST /auth/register — create user with hashed password
  • POST /auth/token — OAuth2 password flow, returns access_token
  • oauth2_scheme + get_current_user dependency
  • Protecting routes with Depends(get_current_user)
  • Token expiry (exp claim) and 401 Unauthorized response
  • Mini challenge: Add token expiry check that returns a clear error message

Section 9 — Final Challenge

Build a complete Booking feature from scratch: 1. Booking router with POST /bookings, GET /bookings/me, PATCH /bookings/{id}/cancel 2. JWT-protected — only authenticated users can book or cancel 3. Business rule: cannot book a trip with 0 spots_available 4. Middleware logs every booking request 5. Verify via Swagger UI at /docs

Solution provided in a collapsible <details> block.

Style Conventions (matching existing PRG400 notebooks)

  • Opening quote in markdown italics
  • Learning objectives as numbered list
  • Section headers: ## Section N — Title

  • Tables for comparisons and summaries
  • bash fenced blocks for terminal commands
  • Closing summary table + further reading links
  • Mini challenges in bold at end of each section
  • Final challenge has hidden solution in <details> block
